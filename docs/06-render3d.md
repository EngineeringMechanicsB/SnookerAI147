# 06 3D 场景与渲染

## 1. 场景目标

3D 不是把 2D 台面“立起来”，而是做一个能看的台球厅：

- 台面、木框、库边、袋口；
- 球、球杆、架杆；
- 三盏吊灯、墙面、吧台、酒架、挂画、飞镖盘、球杆架、霓虹灯；
- 地板/地毯、窗、环境光和阴影。

同时必须保证俯视 3D 和 2D 的画面一致，玩家不会因为切视图而看错球位。

## 2. 相机

`render3d.js` 提供两种相机：

### 俯视正交

- 正交相机，视锥对齐逻辑画布；
- 画面接近 2D，但保留球体、阴影和木框的立体感；
- 默认视图，适合瞄准和判断线路。

### 透视轨道

- 透视相机，围绕台面中心旋转；
- 鼠标拖动改方位角和俯仰角；
- 适合看场景、看袋口、看球杆。

两种相机共用同一份球位和瞄准参数。切相机不重置球局。

## 3. 坐标映射

物理用 `(x, y)`，three.js 用 `(X, Z)`：

```text
X = x - 台面中心 x
Z = y - 台面中心 y
Y = 高度
```

球心高度是 `BALL_R`，台呢高度、库边高度、木框高度分别定义。所有球、
袋口、粉块都按这个映射摆放，避免 2D/3D 位置不一致。

## 4. 球体

- 球体用 `SphereGeometry`，半径和物理一致。
- 球面贴图区分全色/花色/号码。
- 物理层的 `wx/wy/wz` 映射成 three.js 四元数增量，球在移动时真实自转。
- 角速度缺失时用线速度反推滚动轴。

早期球是“滑过去但不转”，看起来像贴图在平移；加入四元数后才有滚动感。

## 5. 灯光与阴影

场景里有三盏吊灯。当前实现：

- 三盏灯都开 `castShadow`；
- 阴影贴图 1024×1024；
- 每盏灯有独立的阴影相机；
- 球的影子会朝不同方向落，形成多道影子；
- 吊灯有轻微摆动，偶尔“阵风”会加大摆幅。

一开始只有中间灯投影，用户指出“三个灯应该对应好几个影子”，于是改成三盏
都投影。代价是每帧阴影渲染成本上升，所以场景里大量重复物件用
`InstancedMesh` 控制 draw call。

## 6. 袋口铜包边

袋口包边是 3D 里返工最多的细节之一。

### 错误方案

1. 以袋口中心画一个完整圆环：看起来像“井盖”，不是包边。
2. 用直条拼十字：中间出现十字交叉。
3. 画在台面内侧：包住了与球桌接触的面，方向反了。

### 最终方案

包边只放在**不与球桌接触的外侧**：

- 中袋：半圆弧，圆心朝台面外。
- 角袋：四分之一圆弧，圆心在台面内角方向的反向。
- 用 `TorusGeometry` 的 `arc` 参数控制圆弧长度，再旋转到正确朝向。

具体是：

```text
中袋：centre = p.y < T ? -PI/2 : PI/2，arc = PI
角袋：centre = atan2(sy, sx) + PI，arc = PI/2
geo.rotateZ(centre - arc/2)
rim.rotation.x = PI/2
```

这样铜边沿着库边外沿走，不会包住台面，也不会悬空。

## 7. 库边粉块

粉块是后加的装饰：

- 新开一局在库边木框上随机放 1~2 块；
- 之后每 10~20 杆再出现一块；
- 最多 3 块；
- 只放库边，不进台面、不进袋口；
- 2D 和 3D 都贴合木框。

3D 粉块是上下两个 box：

- 下半黑色底座，`10 × 4 × 10`；
- 上半彩色粉面，`10 × 3 × 10`；
- 组放在库边木框顶面 `CUSHION_H + 3`。

早期用单色方块，用户要求“上彩下黑”，于是改成两层。3D 里曾经引用
`RAIL_H` 报 `ReferenceError`，因为 `RAIL_H` 是建桌函数的局部变量，后来
改用模块作用域里的 `CUSHION_H`。

## 8. 球杆与架杆

球杆是分段模型：

- 先角；
- 前节；
- 后节；
- 握把；
- 黄铜尾帽。

不是一根圆柱，避免“杆头比杆尾粗”。白球离库边超过约 470px 时显示架杆；
架杆有自己的长杆，不参与物理。

## 9. 场景细节

为了画面不空，场景里加了很多低成本物件：

- 双色墙面：深色木护墙板 + 灰绿灰泥；
- 腰线、踢脚、顶角线、壁柱；
- 吧台、酒架、酒瓶、倒挂酒杯、水果碗、调酒壶；
- 挂画、挂钟、飞镖盘、球杆架、壁灯、霓虹 “147”；
- +Z 墙靠左一扇关着的木门（门框/门板/内凹板/黄铜把手）；
- 窗户和窗外光；
- 地毯、浮尘、场景雾。

重复物件用 `InstancedMesh`，避免每个线脚、每把椅子都单独 draw。

## 10. 性能

- 俯视 3D 约 132 次绘制调用、2.65 万三角面（当前场景量级）；
- 阴影只开必要的灯；
- 浮尘在俯视正交下自动隐藏；
- 低帧率时不强行追帧，物理和渲染同帧推进。

## 11. 色彩管理

three.js r149 默认色彩管理会把 sRGB 贴图二次提亮。项目里：

- `THREE.ColorManagement.legacyMode = false`；
- Canvas 纹理标记为 sRGB；
- 台呢/木框颜色按线性空间设置。

不做这一步，台呢会偏亮、木框发灰，和 2D 的配色对不上。

## 12. 2D/3D 一致性检查

改 3D 位置时，至少检查：

1. 球的 `(x, y)` 在 2D/3D 是否同点；
2. 袋口捕获圈和 3D 袋口是否对齐；
3. 粉块是否在木框上、不穿模、不悬浮；
4. 球杆在俯视和轨道视角是否都指向瞄准方向；
5. 阴影是否跟着灯和球走。

这些检查不靠“看起来差不多”，而是用固定球局截图对比。

## 13. 相机进入 3D 的规则

默认始终是正交俯视。**不会因为闲置自动切到 3D**。

进入透视轨道的两种方式：

1. 按 3D Orbit 按钮 / `O`；
2. 在画面上用右键（或中键）拖动。

进入后：

- 相机飞向 `ORB_DEFAULTS`：`pol 1.00`、`dist 1800`，比旧版更近、更俯视；
- 闲置 60~90 秒随机后，才开始缓慢自转；
- 鼠标拖动、滚轮、方向键会立即打断自动旋转；
- `C` 回俯视，`Esc` 退出轨道。

之前是“闲置一分钟自动飞进 3D”，会在用户只想安静看球时强行转镜头。现在
自动旋转只发生在“用户已经主动进入 3D”之后。

## 14. 俯视时隐藏房间

`render3d` 建完房间后，把房间物件整体收进 `roomRoot`（灯光和灯组除外）。
正交俯视（`perspCam === false`）时 `roomRoot.visible = false`：

- 只画球桌、球、球杆、袋口、库边；
- 灯光仍留在场景里，台面照明和球的影子不变；
- 房间的墙体/家具/门/黑板不参与绘制，省 draw call；
- 进入 3D 轨道后 `roomRoot.visible = true`，房间完整显示。

灯组的 SpotLight 不能跟着隐藏，否则台面会突然变暗，所以 lamp group 被
排除在 `roomRoot` 之外，只隐藏灯罩 `vis`。

## 15. 画质档

`render3d.setQuality(name)` 支持 `auto/low/medium/high`：

| 档位 | 像素比 | 主光阴影 | 吊灯阴影 | 浮尘 |
|---|---:|---:|---:|---|
| Low | 1.0 | 512 | 512 | 关 |
| Medium | 1.5 | 1024 | 768 | 开 |
| High | 2.0 | 2048 | 1024 | 开 |
| Auto | 按 `hardwareConcurrency` / `deviceMemory` 选 | | | |

**球桌和球的几何/材质不降级**。低档只减少阴影、像素比和环境粒子，不影响
台呢、木框、球面贴图的精度。

## 16. 夜空与可点击物件

- 夜空：窗洞外一块 180 点的 `THREE.Points`，只在 Night 显示，透明度缓慢
  呼吸。窗玻璃 `depthWrite:false`，星点才能透出来。
- 可点击物件：
  - 酒杯：`makeGlass()` 改成 Group，`userData.interact='glass'`；
  - 吊灯：`buildLamp()` 的外层 Group 注册为 `lamp`；
  - 花瓶：`buildVase` 的 Lathe 网格注册为 `vase`；
  - 排行榜黑板：`board`。
- `pokeObject()` 用射线找最近物件。酒杯/灯/花瓶进入 `pokeAnims`，指数衰减
  晃动 1.4 秒；黑板不晃，直接返回 `'board'` 给 `main.js` 打开榜单。

## 17. 墙上排行榜

`makeLeaderboard()` 在 +X 墙、时钟旁边放一块 512×360 的 Canvas 纹理黑板。
排行数据来自 `localStorage` 的 `snk.leaderboard.v1`：

- 分数降序；
- 同分用时升序；
- 最多 10 条；
- `setLeaderboard(entries, title)` 重绘纹理。

板面显示前 8 条，点击黑板由 `main.js` 打开完整弹窗。
