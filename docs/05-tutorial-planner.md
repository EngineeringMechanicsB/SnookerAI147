# 05 教学与三点规划

## 1. 教学模式的定位

教学模式不是“规则说明书”，而是一套可重复练习的课程。目标是让玩家在
真实物理下感受杆法，而不是看动画。

课程数据在 `js/tutorial.js`，界面和判定在 `main.js`。教学运行时：

- 禁用正常 AI 和正常计分；
- 摆指定球局；
- 显示目标圈/目标线；
- 玩家出杆后跑真实物理；
- 按课程条件判定通过/失败；
- 可看 `Watch demo` 自动演示；
- 进度存 `localStorage`。

## 2. 课程结构

当前 4 课 15 步：

### 第一课：单球加塞

1. 中心击球 / 定杆
2. 杆角与抬杆
3. 高杆
4. 低杆
5. 右塞
6. 左塞
7. 高杆 + 右塞
8. 高杆 + 左塞
9. 低杆 + 右塞
10. 低杆 + 左塞

每一步只摆少量球，目标圈告诉玩家“白球应该停在哪”或“目标球应该去哪”。

### 第二课：两球叫位

1. 打红叫黑
2. 打黑叫红
3. 打黑同时拆球堆

拆球堆那一步曾经设计成“长台薄黑 + 强低杆往回叫”，用户指出不现实：球堆
在另一侧，根本够不到。后来改成“直线黑球进中袋，白球低杆撞进球堆”，
更接近真实局面。

### 第三课：库边加塞

1. 顺塞（running side）
2. 反塞（check side）

目标不是“记住左塞往哪拐”，而是看同一入射角下，顺塞/反塞如何改变反弹角。

### 第四课：开球

1. 标准开球：薄碰红球堆外侧，白球回开球区。

## 3. 每一步的数据

每个 step 大致包含：

```text
title       标题
goal        目标
focus       本步重点
tip         操作提示
coach       教练笔记：目标 / 动作 / 白球线路 / 常见错误
demo        演示杆法
setup       摆球函数
check       通过判定
```

`coach` 是后来补的。早期教学只有一句“打高杆”，用户反馈文字太稀、太硬。
补充后采用职业教练的口吻：先说目标，再说动作，再说白球线路，最后说常见
错误。

## 4. 演示

`Watch demo` 不是播放预录动画，而是用固定杆法跑真实物理：

1. 保存当前球局。
2. 应用 demo 杆法。
3. 跑 `simulateShot`。
4. 把结果逐帧播放。
5. 约 2.6 秒后重置，交给玩家重复。

这样演示和玩家实际出杆完全同源。演示进不了的球，说明课程设置本身有问题，
会立刻暴露。

## 5. 通过判定

判定不是“看球进没进”这么简单。每一步有自己的 `check`：

- 目标球是否落袋；
- 白球是否停在目标圈内；
- 白球是否碰到指定库边；
- 是否先碰指定球；
- 是否没有犯规。

判定使用真实物理结果和 `rules.judge()`，不用脚本假装。

## 6. 进度

教学进度存在 `localStorage` 的 `snk.tutorial.done` 下。完成一步就记一步，
下次打开菜单可以看到进度。清除浏览器数据会丢进度，这是预期行为。

## 7. 三点规划

三点规划是练习辅助，不是 AI 代打。玩家依次点击：

1. 白球必须先碰哪颗球；
2. 被撞球最终到哪；
3. 白球最终停哪。

`js/planner.js` 搜索瞄准角、力度、左右/高低塞，返回最接近的真实物理解。

### 搜索结构

- 第一阶段：在命中窗口内枚举角度，力度 6~36，不加塞，按目标球误差保留
  前 20。
- 第二阶段：对前 20 组加不同塞和力度倍率，按
  `objErr + 1.25 * cueErr + 塞惩罚` 评分。
- 只保留“目标球终点”和“白球终点”都接近玩家点击位置的结果。

搜索用的是真实模拟，不是几何近似；所以规划出来的线路在实机里能复现。

### 应用方案

`Apply` 把方案写入当前出杆参数，并锁定瞄准方向：

- 锁定后鼠标移动不再改方向；
- 点台面解锁；
- 2D/3D 都保留，不强制切换视图。

早期版本应用后鼠标一动方向就跑了，因为 `aimAt` 还在跟随鼠标；后来加了
`setAimLock(true)`。

### 3D 显示

3D 下用台面条、目标圈和轨迹线显示规划：

- 目标球路径；
- 白球路径；
- 两个终点标记；
- 力度百分比、塞法、误差。

2D 也用同一份 `plan` 状态画叠加层。两边的坐标都来自逻辑台面，不需要各自
维护一套。

## 8. 教学与规划的 UI

教学/规划面板最初是控制条里新增的一行，显示时会把球台挤小。后来收进
固定 22px 的状态行：

- 教学显示课程名、步骤、目标；
- 规划显示误差、力度、塞法、`Apply`；
- 状态行高度不变，球台尺寸稳定在 1387×587。

## 9. 踩坑

- 演示球局和玩家球局共用同一份 `G.balls`，演示结束必须恢复，否则玩家
  接着打的是演示后的球位。
- 规划搜索在 3D 轨道下曾经强制切回 2D；后来去掉，3D 用台面条和轨迹线。
- 规划应用后如果玩家点台面，应该解锁并允许重新瞄准，而不是永久锁死。
- 教学判定不能只看“球进了”，否则玩家用错误杆法碰进去也算过；每步必须
  检查白球停位/首触/库边。
